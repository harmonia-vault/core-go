# Windows 跨槽密文原生复验

本记录仅覆盖本地密钥存储测试，不代表 Windows Service、正式安装器或无人登录环境同步已验收。

在隔离 Windows ARM64 VM 的合成普通用户中，首轮三个主测试有两个通过、一个失败；九个篡改子测试通过。失败断言仅要求 ErrCorrupt，却把任何其他错误输出为“密文被接受”，当时没有记录实际错误或明文长度。该原始失败保留。

原因已经本轮真实 Windows 执行确认：用 os.WriteFile 新建的目标夹具继承 ACL，未设置存储层要求的受保护 DACL，因此先返回 ErrPermission，明文长度为零。没有证据表明它通过了跨槽认证。

修正仅涉及测试夹具：保留旧夹具并断言错误及零明文；随后由真实 Vault.Save 创建受保护目标槽、验证合法读回，再把跨槽密文写到这个现有文件。真实 fs.Read 的字节相等断言确认已越过 ACL 检查，最终仍严格要求 ErrCorrupt 且零明文。产品代码和权限规则未改。

2026-10-04 实际结果：

- Windows 单项复验：1 个主测试、9 个篡改子测试全部通过，主项 0.11 秒；stderr 空，无超时、截断，子进程已排空。
- 执行身份：原合成普通用户会话，非管理员、非提权；没有切换用户、借用令牌或 Task Scheduler。
- 原通过的两个主测试本轮未重复运行。
- 宿主该单项 race、协调器 parser race、Windows ARM64 交叉编译及 vet 通过；宿主结果不替代原生权限证据。
- 四份原始结果已私下保存核对；本轮有标记的文件和空目录精确清理通过，未递归删除其他路径。

只使用合成材料，未读取真实凭据或用户环境变量。原始日志中的 VM 路径和测试账号不公开。
